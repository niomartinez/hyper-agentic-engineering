## Decisions to review

- Real upstream archives broke the old reader. `addyosmani/agent-skills` ships a `.opencode/skills` symbolic link and the reader refused any link member, so the whole repository could not install. The existing `mattpocock/skills` pin ships a root-level `AGENTS.md` symlink and failed the same way, so the relaxation also repairs the current development source's download path. Members are never extracted or followed, so links outside the pinned paths are now ignored; a link at a selected path and special members (devices, pipes, linked directories) are still refused. This is a deliberate relaxation of a validator; the old symlink test became focused tests, including a root-level `AGENTS.md` link fixture.
- `context7-mcp` is not pinned (the task named `find-docs` and `context7-cli`). Pinning it means removing its `OMIT` entry in the exporter and regenerating the lock.
- Core behavior changed in the shared router: the `graph` route no longer needs `--explicit`, so core `skills route --task graph` selects a graphify already in the standard personal folders; the router gains the ten full-team task names; the core `hae-engineering` skill and the `engineering` practice no longer call graph analysis an explicit opt-in. This is deliberate (graphify-first on every host) and is not gated by profile. The `graph` route's `optional_source` still reports the core catalog commit, not the 0.9.92 pin.
- Semantic layer and hooks default to off in the managed instructions: the semantic layer needs the user's authorization, and graphify hooks or merge drivers are installed only on request. A user can opt into more automation; this is HAE's shareable default.
- Commit trailers: the branch commits carry `Co-Authored-By` trailers (Claude Sonnet 5.5 on the implementation commits, Claude Opus 5.5 on later ones); the owner kept them for this personal repository.
- Routes for full-team-only repositories take their `optional_source` from the team manifest instead of adding entries to the core reference catalog.
